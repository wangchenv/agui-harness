目标：把已有规范中反复手写的控制和验证流程，变成有明确边界的可复用代码。沿用现有五个 Skills、contract 和 gate，不重写已有应用。

| 工作包 | 本次交付 | 验收条件 |
|---|---|---|
| A · 本地执行模块 | `agui_runtime`：可信宿主身份、动作白名单、内容绑定批准、期限、撤销、SQLite 原子提交与回执重放 | 独立数据库断言覆盖越权、并发重复、内容变更、期限、故障回滚、重启恢复；两个不同领域使用同一模块 |
| B · 可复跑验证 | Playwright 浏览器适配器、原始 trace/截图；逐样本模型评测与人工配对基线接口 | 自动驱动实际页面；故意破坏 UI 时失败；离线样本只能验证评测器，不能产生 live_model 通过证据 |
| C · CI 与治理 | 实际 GitHub Actions、负控、证据归档、必需检查配置说明与只读检查脚本 | 本地完整检查通过；推送后读取真实 CI 结果；没有管理权限时明确报告保护未验证 |

实施顺序：A 的契约与失败测试 → A 实现 → B 适配器及负控 → C 工作流 → D 文档/回归/提交。每个包以可观察结果验收，不以文件存在算完成。

## 明确取舍

- Runtime 仅覆盖**同一 SQLite 数据库事务**。handler 必须使用传入连接，不能自行提交、另开写连接或调用外部写接口。跨服务 unknown、补偿、队列、SSO 和部署不在此模块提供的保证内。
- Actor 必须由宿主认证；每次 propose/approve/execute/read/revoke 都调用宿主授权函数。模块不把模型字段当身份，不实现身份提供商。会话撤销由授权函数检查。
- operation ID 在提案创建时固定；执行不接受另一个调用者自选 ID。一份提案只能产生一次业务效果。
- 浏览器样例检查交互原型，原型的模拟数据不会升级为真实后端业务证据。目标应用仍需自己的业务 oracle。
- 模型评测由项目提供明确的调用器、评分器与真实配对基线；缺配置、调用失败或缺人员数据必须失败/跳过。不会自动发现密钥或发出付费请求。
- GitHub Actions 文件不等于分支保护。禁止伪称已启用 required checks；仓库规则需要有管理权限的身份配置并核对。

## 真实环境依赖

当前仅有 Git SSH 写权限，未确认 GitHub 管理 API 权限。真实模型配置和代表性人员基线待提供。可独立完成的代码、离线验证和 CI 必须继续；真实质量和强制合并保护分别保留状态。
