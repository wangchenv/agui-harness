# 企业共享会议设备预约：设计范围与责任

这是设计产物；未实现服务、调用模型或访问企业系统。contract 的 ready 只表示设计结构已完成。

## 一条完整旅程

员工输入会议时间、园区与设备需求 → 查看可用实物 → 选择准确设备与时间 → 提交确认卡 → 后端原子占用成功并显示预约号；若竞争失败，留下冲突请求并提供下一步。
园区管理员查看其辖区内冲突请求 → 建议其他设备/时间，或驳回请求并说明原因 → 员工自行确认替代方案并发起新预约。
现有事实只有“预约后端提供原子时间段占用接口”；没有提供接口文档、认证方式、幂等支持和查询能力。
这里没有假定已知后端具有未被证实的能力；它们在 operations.md 中作为启用写入前的依赖。

## 风险与范围决定

员工可查询自己可借用的设备并为自己提交预约；没有代理他人预约权限。
管理员可处理其负责园区的待处理冲突请求；管理员角色不自动获得取消已确认预约的权限。
本设计的“处理冲突”明确为替代建议/驳回，不包含强制抢占、撤销他人预约和批量迁移。
任务负责人已确认此范围；如未来需要强制调度，必须重新设计权限、通知授权、取消原子性与补偿。
自动执行仅包含只读查询、解释、生成有期限的方案以及已批准 operation 的幂等执行/对账。
提交占用为 R2：会消耗其他员工可用的稀缺设备，需要用户确认准确设备和区间；不是要求对每次只读问答批准。
管理员的建议/驳回为 R1：只修改本地待处理请求，不改变占用；以用户在卡片上的明确动作作为本次授权。
不引入付款、外发通知、周期预约、长期偏好记忆、自动换设备和多 Agent。
默认不改变现有已确认预约；取消/改期尚无后端能力信息，明确不在本次功能范围。

## 部署与数据流（计划）

可采用单体 API + 关系数据库 + 一个恢复 worker + Web UI；无需为了 Agent 建设独立微服务群。
Web UI → 认证 Host → 受控工具执行器 → 设备目录/预约适配器。
Host 使用组织 SSO 提供的 principal，服务端解析 tenant、employee、site scopes 和 roles。
模型仅获得最小必要字段和受控工具；不能选择 tenant、充当管理员或签发 approval。
执行器拥有提案/批准校验、幂等记录、deadline、审计与错误分类；业务适配器保留后端原子时间段占用语义。
数据层保存 session、turn、proposal、operation、approval、conflict_case、event log 与 outbox。
设备目录对设备存在、启用状态、借用规则负责；预约后端对是否占用及预约编号负责。
本地 operation 记录对执行过程负责，不得仅凭本地 status 把远端占用判为成功。
冲突工作台对待处理请求的处理决定负责，其 receipt 与预约成功 receipt 必须是不同类型。

## 协议选择

初版使用 HTTP 动作/状态查询与 SSE 增量展示即可；采用 AG-UI 时只增加事件 adapter。
AG-UI 生命周期、文本、工具和状态事件用于传输；RUN_FINISHED 只结束一次 run。
业务 proposal、receipt、设备证据与 seq 映射属于本应用扩展，不能声称它们是官方协议固定字段。
断流、模型结束、页面卡片 final 都不是设备已占用的证据。
所有页面按钮与聊天请求经过同一 Host/执行器，不存在绕过权限和 operation 的快捷写路径。

## 分离三个状态

turn：queued / running / completed / interrupted / failed；记录一次会话执行，不负责声明业务提交。
operation：proposed / approved / executing / committed / failed / unknown / expired；独立持久化，页面关闭后继续对账。
presentation：partial / final / invalidated；final 仅表示完整校验后的卡片，有 receipt 才能显示业务成功。
会话重置、turn 中止、用户注销不会逆转已发生的占用；界面必须能重新查询真实结果。

## 可验收的边界

员工不能读其他租户记录，不能为其他员工占用；管理员不能处理其他园区请求。
同一设备的重叠区间不出现两个 confirmed 预约；邻接区间 [09:00,10:00) 与 [10:00,11:00) 可以共存。
重复提交返回同一个结果；远端超时显示“正在核实”，而不是提示用户再创建一个预约。
模型不可伪造预约号、把管理员建议说成预约成功或从设备描述中的指令取得权限。
实际模型质量、人工效率和负载指标尚未测量；设计门禁通过不能替代它们。

## 实施前待核实

SSO claims/园区管理员范围、设备目录的版本字段、后端幂等与按客户请求号查询接口。
企业预约时长/提前期政策：设计测试暂用单次最长 4 小时、提前最多 30 天，可配置而非认定企业已有制度。
人工现有操作基线：暂定义目录/日历/管理员工作台完成相同任务；实施时应替换为真实当前流程并采样。
