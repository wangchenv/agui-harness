# IT 服务台：交互与视觉参考

直接用浏览器打开同目录的 `index.html` 即可。所有 CSS、图标和 JavaScript 都在文件中，无 React、npm、CDN、外部字体或网络请求。可以离线运行。

这是本项目编写的高保真交互原型，供未来 coding agent 参考信息层级、真实业务状态与界面表达。它不是已连接后台的服务台，也没有实现生产认证、授权、持久化或可靠提交。

## 信息与视觉结构

- 左：紧凑工单队列、搜索、状态筛选。选择工单会同步中部与助手上下文。
- 中：工单内容、当前优先级、责任人、完成时间与带来源的证据；处理记录是独立页签。系统检查与申请人陈述明确区分。
- 右：建议理由、可选择的目标优先级、准确 before/after 预览，以及当前调整的处理结果。
- 顶部可切换用户/运营视图。用户只看自己的演示请求，提交草稿供服务台审查；运营视图可以审查与批准。前端切换仅演示体验，不能替代服务器权限。

配色、间距、圆角、字体与阴影集中在 `:root` CSS tokens。宽屏使用三栏；中等宽度将助手放到详情下方；手机全部纵向排列，初次打开时队列与助手折叠。目标检查宽度为 1440、768、390 像素。

## 可点击流程

1. 默认运营视图选择 `T-2048`，保留目标 `P2 · 高`，点击“起草优先级调整”。
2. 生成阶段仅显示 partial，不可审批；完成后出现 P3 → P2 的准确预览。
3. 点击“审查这项变更”，在独立审查窗口核对 before/after，再“批准并记录”。
4. 本地模拟记录确认后，工单优先级与处理记录同步变化；卡片显示明确标记为模拟的记录编号。
5. 切换用户视图：可以提交审查请求，但不能执行批准；切回运营视图可继续同一草稿。

在起草前通过助手底部“演示情境”选择其他流程：

- **建议生成中断**：partial 后进入 interrupted，不出现可审批预览，也不声称工单变更成功；“重新整理建议”回到正常生成流程。
- **提交结果待确认**：批准后进入 unknown。新的起草/重复提交按钮禁用，界面保留原工单投影；点击“核对处理结果”读取同一条页面内模拟记录，确认后才更新优先级。核对不会生成新 operation。
- 放弃尚未应用的草稿不会改变工单；已解决工单不提供优先级调整入口。

所有模拟状态仅在页面内存中，刷新会恢复初始数据；没有真实工单被写入。`simulationLedger` 只是演示确认和 UI 投影之间的关系，不是持久 operation store 或可信 backend。

## 状态映射与接入边界

三个关键层次分别为 **partial（未完整/不可操作）→ validated draft（完整提案，可审查，未提交）→ committed（有模拟记录确认后展示成功）**。另外显式处理 interrupted、awaiting review、applying、unknown 与 reconciling，避免把渲染完成当业务成功。

页面局部变量 `phase='draft'` 对应 validated preview；`expectedVersion` 和 before/after 用于展示提交前变化检查。真正接入系统时必须替换为可信 host、服务端领域校验、提案 hash、当前权限、版本条件写、持久幂等 key 和权威 receipt。浏览器内 Map、禁用按钮、版本数或角色标签不能提供这些保证。

可访问性包括语义地标、跳转主内容链接、原生可折叠区域与 dialog、键盘焦点样式、tab 页签方向键、队列上下键、状态的文字与颜色双重表达、`aria-live` 通知及降低动态效果支持。审批窗口支持 Escape 关闭。没有把原始工具 payload、SQL、模型 token 等实现细节放进普通用户流程。

建议人工验收：三个视口检查横向溢出、长标题换行、审查对话框和折叠区；用键盘完成起草/取消/批准；分别运行正常、中断、unknown 恢复；确认每次反馈都保留“交互原型 · 本地模拟”的事实边界。

## 可复跑的状态检查

```sh
node examples/ui-workbench/test-state.cjs
```

从插件根目录运行；也可以在本目录执行 `node test-state.cjs`。测试仅需 Node.js 标准库，直接提取并执行 `index.html` 的原始脚本，用 stub DOM 检查 5 组状态转换：正常确认、中断、unknown 核对、用户权限演示、过期草稿。断言失败会非零退出。它不模拟真实浏览器，不能证明响应式布局、焦点行为或可访问性；这些仍需浏览器检查。
