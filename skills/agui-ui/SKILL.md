# 让 Agent 界面支持真实任务

目标是让使用者理解信息、控制操作并完成工作。对话、业务组件和传统页面共同服务任务；不默认把应用做成聊天窗口或指标仪表盘。
本技能是设计与实施指引，不是 UI 框架，也不保证生成界面已可生产使用。

## 从当前任务进入

先读现有页面、路由、设计系统、组件库、样式/token、目标设备及用户要求。有 `DESIGN.md` 或设计稿时沿用并更新；有 `.agui` 时读取已有范围和业务约束，只在当前任务范围内登记设计产物，不擅自改变功能范围或门禁。
小范围调整只处理相关组件和受影响旅程，不借机重建整套 UI。没有设计系统时选择适合任务的方向；已有系统时优先复用，不擅自更换字体、品牌、导航或交互习惯。
视觉偏好不明确时，提出一个有理由、可直接查看的方案并继续制作；把假设和取舍写入交付。不新增“用户批准视觉后才能继续”的形式化门槛。

按需要渐进读取：

- 定义谁在何种场景完成什么任务、页面如何组织：读 [产品与任务设计](references/product-design.md)。
- 选择视觉方向、落地 tokens 与组件状态、适配屏幕：读 [视觉与组件系统](references/visual-system.md)。
- 检查实际渲染、键盘/读屏、响应表现和用户效率：读 [可用性验证](references/usability-validation.md)。
- 写入、审批、receipt 或流式状态涉及业务事实：同时参照 [交互契约](../agui-build/references/interaction.md)，不复制另一套执行语义。

## 实施节奏

1. 明确主要使用者与运营/复核者、优先任务、完成标准、当前流程痛点及数据权限。把未经研究的人物画像标为假设；用户给出的真实材料优先。
2. 用关键旅程、页面结构和低保真线框比较布局。发现信息、执行动作、审查结果可能需要不同界面；选择有助于当前任务的形态。
3. 在可查看的设计方案中确定信息层级、视觉方向及主要组件；读写状态采用同一业务来源。把自然语言入口接到可检查、可修改的结构化内容。
4. 使用 [UI 设计模板](../../templates/ui-design.md)、[tokens 模板](../../templates/tokens.json) 和 [组件清单模板](../../templates/component-inventory.json) 作为结构起点，替换为真实任务与现有风格；复用现有组件制作可运行原型。接入真实服务时遵守已有授权范围，不以原型演示隐式执行外部操作。
5. 在实际浏览器分别检查桌面、移动及中间宽度，保存截图，检查长内容、键盘和状态变化。修复实际发现的问题并复验。
6. 分别报告自动 UI 检查、截图视觉检查、代表性用户任务评估；能运行哪层就交付哪层证据，不能运行的明确写未验证。

## 交付物

默认产出下列文件；项目已有同等资产时直接更新，并在 `DESIGN.md` 中列明真实路径和启动方法。

| 产物 | 可检查的内容 |
|---|---|
| `DESIGN.md` | 用户/任务、信息架构、旅程、线框、视觉取舍、关键状态、设备与可访问性目标、证据及未验证项 |
| `tokens.json` | 可被项目采用的字体、间距、颜色与语义 tokens；单位、映射和既有来源明确 |
| `component-inventory.json` | 复用/新增组件、变体、数据来源、完整状态、动作与权限、键盘/读屏行为、实现和验证位置 |
| `prototype/` 或现有应用入口 | 可启动、可操作的原型；包含任务闭环和代表性异常，注明模拟/真实数据边界；登记具体入口文件 |

截图与检查记录放项目既有证据目录，或 `design-evidence/`；从 `DESIGN.md` 链接。只有图片、代码片段或组件清单不能称为可运行原型。
机器格式采用 [ui-tokens.schema.json](../../schemas/ui-tokens.schema.json) 和 [ui-inventory.schema.json](../../schemas/ui-inventory.schema.json)，详细设计解释放 `DESIGN.md`，不要给关闭扩展字段的 schema 增添自定义键。
在现有 contract 的 `ui_design={spec,tokens,inventory,prototype}` 登记路径；`spec` 指向 `DESIGN.md`。application scope 且启用 UI 时需要该声明；prototype 在 design 阶段可尚未实现，implementation 阶段必须指向实际文件。
这些文件、JSON 字段和目录约定属于本工具包，不是 AG-UI 官方协议字段。交付物存在不等于任何现有 harness gate 自动通过。

运行 [scripts/ui_audit.py](../../scripts/ui_audit.py) 的 `--tokens PATH --inventory PATH` 做静态检查；它只验证声明结构、选定颜色对、组件引用和动作状态，不证明实际浏览器行为。
H06 的 `responsive_layout`、`keyboard_navigation`、`ui_state_recovery` 由 `kind=ui` 检查持有，结果需 `context.execution_mode=browser`；只能来自实际浏览器检查，不能给静态审计贴上 browser 标签。证据绑定和命令 inputs 遵循 [Harness 合约](../agui/references/harness.md)。

## 必须保持的边界

- **MUST〔H06〕** 建议、待执行、核实中与已生效明确区分；成功显示来自权威 receipt。流式结束、动画结束或模型说“完成”都不能证明业务已提交。
- **MUST〔H06〕** partial/过期/权限不足的组件不得触发业务写入；未知结果提供查状态或接管，不能通过重新提交掩盖未知状态。
- **MUST** 沿用已授权范围及业务所需审批，不给所有动作增加确认弹窗；需要确认时清楚展示目标、变更、影响和有效期。
- **MUST** 核心任务能用键盘完成，交互有可辨名称、可见焦点和适当语义；错误与状态不能只靠颜色表达。更完整的可访问性检查见视觉与验证参考。
- **MUST** 自动检查、截图视觉检查与真实用户效率分别报告。未测量的用户收益、读屏表现或设备不能标为通过。
- **SHOULD〔H09〕** 将首次可用内容、操作反馈和最终确认的体验目标与已有延迟预算相连；不能用无限 loading 隐藏超时。
- **SHOULD〔H11〕** 比较完整任务的人工作业、审阅、纠错与接管成本；按钮少、模型生成快不直接代表用户更高效。

优先使用项目已有资产、浏览器和本地开发工具。可选工具只在实际可用且任务授权范围内使用；不自动调用付费 Figma、图像生成或外部素材服务，不依赖其他技能才能完成基本流程。
