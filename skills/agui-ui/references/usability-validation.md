# 验证界面、视觉和真实使用效率

本文件用于原型和已实现界面的实际检查。三类证据分别记录，不能互相替代。
复用已有测试栈和浏览器；不强依赖特定外部 skill、付费工具或设计平台。

## 1. 明确验证对象

记录代码/原型版本、入口、启动命令、数据集、权限角色、浏览器、viewport 和设备模拟方式。
原型用模拟数据时明确标注；UI 看见 receipt 不证明真实后端已提交。
涉及后端的业务 oracle 和故障用例参照 [评测](../../agui-verify/references/evaluation.md) 与 [故障矩阵](../../agui-verify/references/failure-matrix.md)。
优先验证一条完整的主要任务，再覆盖重要异常和实际改动影响；小样式调整无需重做整套用户研究。
定义清晰的可观察预期：找到目标、修改正确对象、看懂影响、完成操作、辨认最终状态。

## 2. 三类证据各自回答什么

| 类型 | 适合检查 | 不证明什么 |
|---|---|---|
| 自动 UI 检查 | DOM/状态断言、表单校验、路由、键盘序列、溢出、自动可访问性扫描 | 视觉层级是否合适、真实读屏是否好用、用户净收益 |
| 截图与人工视觉检查 | 实际布局、排版、密度、长内容、对齐、遮挡、不同宽度 | 业务提交正确、交互完整、真实用户效率 |
| 代表性用户任务评估 | 找得到、理解正确、错误/返工、主动时间、接管和主观困惑 | 事务原子性、全量设备覆盖、任意人群都有效 |

Agent 查看截图可提供视觉检查记录，应注明检查者为 Agent；不声称有人类实际评审过。
人工视觉评审需要实际评审者的记录；只有截图文件存在不能算完成视觉评审。
开发者自测能发现问题，但不能冒充代表性用户任务研究〔H11〕。
**MUST** 已验证、未验证、已知失败分开，保留真实分母；不能把无法执行的项目写成通过。

## 3. 启动并验证原型

使用项目已知启动命令，在本地或授权的测试环境打开真实渲染页面。
执行核心路径，确认按钮、输入、导航和状态变化可以操作；静态 mock 不称为交互完成。
自动化可以用已有浏览器测试栈或可用的浏览器工具；只使用能实际操作目标环境的能力。
没有浏览器能力时可交付可运行代码及检查步骤，标记“未做渲染/截图验证”，不编造截图或结果。
原型测试不接入未经授权的生产写权限，不让批量 fixture 触发真实通知或外部业务操作。
测试产生临时任务/操作时按隔离环境的清理方式处理；清理失败也保留记录。

## 4. 自动 UI 与状态检查〔H06〕

先运行 [ui_audit.py](../../../scripts/ui_audit.py) `--tokens PATH --inventory PATH` 检查 [tokens](../../../schemas/ui-tokens.schema.json) 和 [inventory](../../../schemas/ui-inventory.schema.json) 声明；通过只说明静态声明一致。
实际浏览器检查覆盖 H06 的 `responsive_layout`、`keyboard_navigation`、`ui_state_recovery`。这些 case 的 owner 为 `kind=ui`，结果 `context.execution_mode=browser`；不可用静态审计或截图存在断言代填。
检查脚本、依赖、fixture 与 UI 实现纳入 source snapshot，命令本地脚本及依赖显式写入 checks.inputs；按 [Harness 合约](../../agui/references/harness.md) 生成证据，不手改 receipt。

按实际组件选择断言，不能只测试“页面能加载”：

- 从自然语言或传统表单进入同一业务对象，编辑后双方读取同一版本。
- 核心表单必填、格式和业务错误可定位；错误后输入不会无故消失。
- partial/过期/权限不足时写动作不可触发，未知组件有安全降级。
- 提交中阻止意外重复触发；结果未知时查询原 operation，不发起新的写入。
- receipt 确认才显示生效；明确失败、unknown、部分成功的文案和动作不同。
- 刷新/断线后恢复已知状态；已成功项不因整轮失败而变成“全部失败”。
- 页面/租户/身份切换后，旧流与旧操作不能恢复成可点击的有效内容。

观察事件与界面之外，涉及真实写入时还要查询权威业务记录；截屏不能替代该断言。
自动可访问性扫描记录工具及结果，修复实际问题；零扫描告警不等于可访问性全面合格。
工具不可用时手工检查核心语义，诚实记录自动覆盖缺口，不为跑一个扫描引入大依赖。

## 5. 桌面和移动截图实查

对实际渲染页面保存桌面、移动截图，并操作至少一个中间宽度；示例 1440×900、390×844、768×1024 可作为起点，最终以目标设备为准。
记录 viewport、页面、组件状态、数据和版本；模拟 viewport 不声称为真实设备实测。
关键截图至少包括主要任务页面和此次设计最易出错的状态，如长内容、校验失败或 unknown。
截图应来自真实浏览器，不用图片生成工具制作“验证截图”。
实际打开截图检查，不仅确认文件存在；必要时滚动检查折叠区、弹层和页面下半部。
逐项判断：主要动作是否清楚，信息是否可比较，文本是否裁切，焦点/底栏是否遮挡，空/错/等待是否仍有上下文。
检查移动端内容顺序、软键盘影响、触控目标、横向滚动和弹层退出；桌面不能仅等比缩放。
修复后重新截图受影响状态；保留最终证据，注明旧截图已失效，不混用不同版本证明完成。
涉及敏感材料时用隔离或脱敏数据，证据只保存必要内容。

## 6. 键盘、焦点、读屏与对比度

**MUST** 实际用键盘走主要任务：Tab 顺序、Shift+Tab 返回、Enter/Space 激活、弹层退出及焦点返回。
检查错误后能定位问题，动态更新不会抢走输入焦点，移动/缩放时焦点元素仍可见。
实际测量重要文本、按钮、焦点和语义状态的对比度，记录失败组合并修复。
检查减少动态效果偏好、放大文本和页面缩放；信息不能因这些设置丢失。
在可用读屏环境中验证标题导航、控件名称、输入错误、提交/核实结果及动态通知频率。
Accessibility tree/DOM 检查只能证明语义结构的一部分，不能冒充实际读屏操作。
无读屏工具时明确“读屏未实测”，保留语义检查和待验证清单；不要因此停止其他可完成工作。
**MUST** 无法键盘完成核心任务、不可辨操作名称或错误成功提示等已知问题不能标记为已完成验证。

## 7. 响应体验〔H09〕

分别测量首次可用内容、用户动作反馈、可操作内容和最终确认时间；骨架出现不等于可用。
记录实际网络/设备条件与样本数，使用项目已有 SLO；样本不足时不给 p95 稳定性结论。
慢响应和断线时观察是否保留上下文、是否显示已知状态、是否提供真实可用的退出/接管。
检查连续输入、滚动、重复点击、长列表与流式更新是否卡顿或引发布局跳动。
优化渲染和渐进展示可以减少等待感，但不能通过提前显示“已完成”降低记录的确认耗时。
前端体验良好不证明服务端预算守限；并发、重试和成本仍按运行时控制验证。

## 8. 人工任务效率〔H11〕

选择代表性最终用户/运营人员与真实任务类型；设计者自己的顺畅演示只作为试跑。
比较现有流程与 Agent UI 的相当任务，尽量用等价数据和交叉顺序降低学习效应。
记录是否完成、正确性、主动操作时间、审阅/纠错/接管时间、等待、误操作和返工。
让参与者自行寻找入口和处理例外；主持人提供帮助时计入记录，不能悄悄指导后标为独立完成。
额外记录：是否理解建议与已生效的区别、是否知道结果未知时该做什么、是否信任正确的证据。
净人工节省采用完整主动时间差；增加审批、重复确认或复核负担应算入成本。
报告样本、任务、基线版本、界面版本、失败及局限，不把少量定性访谈换算成稳定成功率。
没有实际参与者或人工基线时交付任务脚本和评估计划，结论标为“用户效率未验证”。
真实用户评估与 live model_eval 各有用途；不能拿截图、自测或脚本模型结果代填现有 harness 的 H11 证据。

## 9. 可复查的交付记录

在 `DESIGN.md` 链接原型、tokens、组件清单、最终截图及检查记录，说明如何复跑。
每项问题记录页面/状态、观察、影响、修复和复验结果；未修问题给出适用范围及后续条件。
总结采用“自动 UI 已测 / 视觉已查及检查者 / 用户任务已测或未测”的分层表述。
不因为截图漂亮而跳过失败路径，也不因为技术断言通过而宣布产品易用或适合所有业务。
