# 以真实结果验证 AGUI 应用

## 先确定验收范围

读取 contract、相关源码和 [Harness 合约](../agui/references/harness.md)，用 status 识别证据缺口。设计检查、确定性实现检查、发布证据是不同层次。scope=reference 不能通过 release。

按涉及的控制读 [故障矩阵](references/failure-matrix.md)，按模型/性能/人工效率需求读 [评测规范](references/evaluation.md)。不为与变更无关的模块重复做昂贵测量。

需要实际 adapter 时读 [评测接口](../../docs/EVALUATION.md)：浏览器 runner 保存 trace/截图；模型 runner 当前只支持结构化精确匹配，离线示例明确跳过质量/效率。0.2 的 ui/model_eval 必须带可重新核对摘要的原始 artifacts。需要强制合并门禁时读 [CI 接入](../../docs/CI.md)，分别报告 workflow 运行结果与仓库保护状态，不用前者代替后者。

## 运行与判定

1. 静态检查：源码身份边界、schema、工具副作用、工作流与组件一致；运行 lint。人工确认 source_paths 包含本次相关实现、测试、prompt、配置与依赖锁文件。
2. 确定性测试：审阅 adapter，再运行 run；包含重试、超时、提交丢回包、审批过期、并发、session reset、UI中断和memory删除等适用场景。用独立最终状态作为 oracle。
3. 负控：让一个已知错误实现/开关经过同一测试；它应非零退出且相应不变量失败。禁用测试、放宽阈值或伪造报告不能修复失败。
4. 真实质量：在已有授权和测试端点下运行 `run --include-live`；model_eval 必须真实调用指定模型，记录 model/dataset/baseline 版本。模拟模型仅能验证边界，不能计作质量样本。
5. 性能与恢复：load 测端到端延迟/并发/费用，recovery 测重启、丢回包、外部 unknown 对账和可见状态；明确哪些后端是 mock。
6. 执行相应 stage gate，列出未通过控制、证据与修复。代码/合同/检查器变化会使旧证据失效；修复后重跑相关检查，本版本门禁对同一 source scope 的证据统一失效。
7. 更新 STATE/HANDOFF。报告“通过了什么、未证明什么、仍有何阻断”；只有用户授权才进行部署，不把 release gate 当部署指令。

## 真实应用的发布证据

release 同时要求 application scope、确定性/真实模型/负载/恢复证据、适用控制与阈值。阈值须按业务风险校准，不能继承模板的95%/20%示意值就声称适合所有行业。

代码 oracle 判断业务是否正确；经人工校准的 rubric 判断解释质量。记录样本分层与重复运行，避免总平均掩盖高风险类别。比较用户完成时间与运营主动操作/审核/返工时间，而非只比较 tokens。

若缺少模型凭证、真实后端或负载环境，完成已授权的本地验证并列为未验证，不编造 PASS，也不擅自发出真实业务动作。

## 证据可信边界

本地哈希防意外陈旧，不抵御可改写源码与证据的恶意仓库所有者；adapter 是受审查的测试程序。生产 CI 应从可信分支执行、限制证据写权限并保留不可变运行记录。此包不是签名审计系统或生产认证服务。
